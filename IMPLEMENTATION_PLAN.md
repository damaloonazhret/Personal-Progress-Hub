## Модель Today

Сейчас, после Phase 4, в `tasks` записано:

- `in_today` — задача остаётся в Today, пока её не выполнят или не уберут.
- `today_position` — порядок только на экране Today.
- `due_date` — необязательный срок, сам по себе не добавляет задачу в Today.
- `position` — порядок во входящих и внутри проекта.

Это поведение действующего приложения. Целевая модель Phase 6 заменяет `in_today` на `scheduled_date` и описана в `ARCHITECTURE.md`. `due_date` остаётся сроком. Код и миграции этой замены ещё не написаны.

## Phase 6 — согласованный план

Планирование только по датам. Времени начала, окончания, продолжительности, часов и встреч нет. Блоки идут по порядку. К следующему не переходить, пока текущий не принят.

Общие правила:

- Шаблон, правило и вхождение разделены.
- `scheduled_date` — изменяемый день плана. `recurrence_occurrence_date` — неизменяемая исходная дата вхождения.
- Уникальность вхождения: `(user_id, recurrence_rule_id, recurrence_occurrence_date)`.
- Генератор закрывает весь диапазон от `generate_from` до запрошенной даты пакетами. Один пакет короткий. Уникальный ключ и блокировка правила сохраняют идемпотентность. Неполного календаря из-за лимита нет.
- «Сегодня» сортируется по `scheduled_date`, затем по приоритету `high` / `medium` / `low`, затем по `day_position`. Календарь внутри дня использует тот же порядок.
- Перед переносом старого Today создаются `profiles` и часовой пояс. Без профиля дата считается в `Etc/GMT+12`.
- Ссылки на шаблон, правило, сферу и проект — составные внешние ключи того же пользователя. `on delete set null` обнуляет только необязательный идентификатор, не `user_id`.
- Перенос вхождения не освобождает исходную дату. Удаление пишет пропуск. Возврат в активные не создаёт дубль. Отмена правила оставляет задачи. Правка правила не переписывает созданные вхождения.

### 6.1 Templates

Реализовано. База: `task_templates` и `tasks.template_id`. Today на этом шаге не меняется.

Готово, когда можно создать шаблон с названием, описанием, приоритетом и необязательными сферой и проектом, создать из него задачу, изменить задачу отдельно от шаблона и использовать шаблон повторно. Чужая сфера, чужой проект и чужой шаблон отклоняются ключом базы, а не проверкой в коде.

Проверить: создание, повторное использование, независимость задачи, удаление шаблона оставляет задачу и очищает ссылку, доступ только к своим шаблонам.

### 6.2 Recurring Tasks

База: миграция Today из `ARCHITECTURE.md`, затем `recurrence_rules`, `recurrence_skips`, поля вхождения в `tasks`, триггер неизменной даты и триггер пропуска при удалении.

Готово, когда правило умеет каждый день, каждые N дней, каждую неделю, каждые N недель и выбранные дни недели, имеет начало, необязательный конец, паузу, возобновление, изменение, отмену и пропуск одного вхождения. Каждое вхождение — отдельная задача. «Сегодня» читает `scheduled_date <= местная дата` и сортирует по дате, приоритету и `day_position`. Обычную задачу на сегодня можно добавить без правила. Длинный пропуск закрывается пакетами целиком.

Проверить: все интервалы, паузу без заполнения её дней, пропуск, удаление вхождения и повторное открытие страницы, перенос без второй задачи на исходную дату, возврат выполненного вхождения без дубля, отмену без удаления задач, правку правила без изменения старых вхождений, два параллельных пакета, длинный период без таймаута и без пропущенных дат, порядок «Сегодня» при задачах разных дат и миграцию старого Today в часовом поясе профиля.

### 6.3 Calendar

Новых таблиц нет. Появляется раздел «Календарь»: день, неделя с понедельника, переход по датам, создание и перенос, показ повторений. Генератор получает именно видимый диапазон, включая будущие недели.

Внутри дня порядок тот же, что у «Сегодня»: дата уже одна, дальше приоритет `high`, `medium`, `low`, затем `day_position`. Перенос внутри группы меняет позицию. Перенос в другую группу меняет приоритет. После перезагрузки оба значения те же. В самом списке «Сегодня» более старая дата стоит выше. `due_date` дату планирования не заменяет.

Проверить: день, будущую неделю и полный набор её вхождений, длинный диапазон несколькими пакетами, перенос, группы приоритета, сохранность старого `today_position` внутри одной даты и одного приоритета, связь с Today и независимость срока.
