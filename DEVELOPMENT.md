# Development

Рабочая ветка фич не должна совпадать с `main`. Baseline и принятые изменения живут в `main`. Текущая разработка идёт в `feature/phase-1-foundation`.

## Команды

```bash
npm run dev
npm run lint
npm run typecheck
npm run build
```

`typecheck` запускает `tsc --noEmit`. `npm test` проверяет сетку повторений и границы месяца календаря через `node --test`. Vitest и Playwright остаются поздней фазой.

## Окружение

Локальные ключи лежат только в `.env.local`. В репозитории хранится `.env.example` с пустыми именами переменных.

Для Phase 1 достаточно публичных URL и publishable key. Серверные операции идут от имени сессии пользователя. `service_role` приложению не нужен.

## Что уже можно смотреть

Вход и регистрация доступны на `/login` и `/register`. Входящие, Сегодня и Готово работают с реальными задачами. Сегодня читает `scheduled_date` в часовом поясе профиля. Обзор показывает три счётчика. Сферы и проекты создаются, упорядочиваются и показывают свои задачи. Проект нельзя создать без сферы. Шаблоны копируют поля в новую задачу и не меняют уже созданные. Задача из шаблона не получает дату планирования. Раздел «Повторы» хранит правила дня и недели. Открытие «Сегодня» и обзора создаёт недостающие вхождения до местной даты. Раздел «Календарь» показывает месяц с понедельника и перед чтением задач создаёт повторения на видимые полные недели, включая будущие даты.

Тема переключается кнопкой в шапке и запоминается через `next-themes`. По умолчанию используется системная тема.

## База

Схема живёт в `supabase/migrations`. Применённые версии совпадают с именами файлов: `20261106150733`, `20261106150852`, `20261106184533`, `20261106190806`, `20261106191609`, `20261106192650` и `20261107103506`. `20261107103506` добавляет пакетную функцию `generate_recurrence_batch`. Локальный Supabase через Docker не поднимался: миграции применены к облачному проекту.

`src/types/database.ts` сгенерирован из этой схемы. После следующего изменения базы типы нужно сгенерировать заново.
