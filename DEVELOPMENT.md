# Development

Рабочая ветка фич не должна совпадать с `main`. Baseline и принятые изменения живут в `main`. Текущая разработка идёт в `feature/phase-1-foundation`.

## Команды

```bash
npm run dev
npm run lint
npm run typecheck
npm run build
```

`typecheck` запускает `tsc --noEmit`. Отдельного test runner пока нет: Vitest и Playwright относятся к Phase 8.

## Окружение

Локальные ключи лежат только в `.env.local`. В репозитории хранится `.env.example` с пустыми именами переменных.

Для Phase 1 достаточно публичных URL и publishable key. Серверные операции идут от имени сессии пользователя. `service_role` приложению не нужен.

## Что уже можно смотреть

Вход и регистрация доступны на `/login` и `/register`. Входящие, Сегодня и Готово работают с реальными задачами. Сегодня читает `scheduled_date` в часовом поясе профиля. Обзор показывает три счётчика. Сферы и проекты создаются, упорядочиваются и показывают свои задачи. Проект нельзя создать без сферы. Шаблоны копируют поля в новую задачу и не меняют уже созданные. Задача из шаблона не получает дату планирования.

Тема переключается кнопкой в шапке и запоминается через `next-themes`. По умолчанию используется системная тема.

## База

Схема живёт в `supabase/migrations`. Применённые версии совпадают с именами файлов: `20261106150733`, `20261106150852`, `20261106184533`, `20261106190806` и `20261106191609`. `20261106190806` заменяет `in_today` на `scheduled_date` и добавляет `profiles.timezone`. `20261106191609` разрешает проверке пояса выполняться от имени вошедшего пользователя. Локальный Supabase через Docker не поднимался: миграции применены к облачному проекту.

`src/types/database.ts` сгенерирован из этой схемы. После следующего изменения базы типы нужно сгенерировать заново.

## Git

Коммиты на `main` напрямую для фич не делаем. Перед пушем ветки проверь, что в индексе нет `.env.local`, `node_modules` и `.next`.
